## WARN Models - Under Investigation

### `rpt_model_f` - recall=88% | precision=82%

- **Root cause**: Dynamic `WHERE closed_date >= date_add(current_date(), -7)` filter. Legacy
  snapshot was built when more claims were open; dbt rebuilds now when many have closed.
- **Classification**: Category 1 - timing/environment difference. Self-corrects in a live
  daily pipeline where both sides are refreshed.
- **Recommendation**: Accept for static POC comparison.

### `rpt_model_i` - recall=99% | precision=95%

- **Root cause**: 107K extra rows in dbt from 6 raw CDC INNER JOINs without QUALIFY dedup.
  Each CDC revision of a claim/policy creates a duplicate transaction row.
- **Fix**: Apply `QUALIFY ROW_NUMBER() OVER (PARTITION BY id ORDER BY commit_timestamp DESC) = 1`
  to each raw CDC INNER JOIN.

---

## FAIL Models - Code Bugs Found

### `rpt_model_j` - recall=64% | precision=96% → **FIXED**

- **Root cause**: Brand `'Brand C'` missing from `WHERE brand IN (...)` filter.
  Affected 3 model files + 1 YAML test. ~29K claims were silently excluded.
- **How found**: Brand distribution query on the RS side showed a brand absent from the dbt filter.
- **Fix**: Added the missing brand to all WHERE clauses and `accepted_values` tests.

---

## BLOCKED Models - Infrastructure Dependencies

### `rpt_model_l` - recall=1% | BLOCKED ⛔
- **Reason**: Source `datashare_sor_protect` not provisioned in target environment.
  The migrated code is correct; the data pipeline is missing.
- **Ask**: Provision the PROTECT datashare into the target Databricks workspace.

### `fct_model_n` - recall=20% | BLOCKED ⛔
- **Reason**: Event matching pipeline (`int_event_daily`) only has event data through
  date X; legacy has events through date X+50 days. Gap closes when pipeline is refreshed.
- **Code fix applied**: Corrected LEFT JOIN → INNER JOIN (model is event-scoped).
  Row count normalised from 1.8M → 33K after fix.

> **Coverage formula excluding BLOCKED models**:
> `coverage % = PASS / (total - BLOCKED) × 100 = 5 / 11 = 45%`

## Build Performance

| Scenario | Wall Time | Notes |
|---|---|---|
| Full rebuild - original (all tables) | **~70 min** | Baseline before CDC dedup fixes or incremental conversions |
| Full rebuild - after CDC fixes | **~18 min** | QUALIFY dedup reduced fan-out in heavy intermediate models |
| Full rebuild - after incremental conversions | **~15 min** | 19 models converted to incremental (`--full-refresh` still needed) |
| **Estimated daily incremental run** | **~5-7 min** | Only new/changed CDC records processed per watermark |

**Key incremental conversion targets**: The heaviest `table` models are the most valuable to
convert - a single large intermediate model (e.g. `int_pi_home_transaction`, 7m30s) can
dominate the build time. Convert after confirming grain/unique-key.

## Analysis Files - How to Run

> All files in `analyses/redshift_comparison/`. Compile with `dbt compile`, then paste compiled
> SQL into your warehouse SQL editor, or run via `dbt show --select <model>`.

| File | Purpose | Step |
|---|---|---|
| `01_pk_coverage.sql` | PK match summary - recall + precision - across all models | Step 5 (gate 1) |
| `07_coverage_report.sql` | Step 7 coverage % with PASS/WARN/FAIL/BLOCKED status | Step 7 |
| `pk__<model>.sql` (N files) | Per-model PK audit_helper row detail | Step 5 drill-down |
| `col_diff__<model>` (dbt views) | Column-level match rates - `compare_all_columns(summarize=true)` | Step 5 (gate 2) |
| `col_diff_a__` / `col_diff_b__` (dbt views) | Date-filtered upstream relations for `compare_all_columns` | Step 5 (gate 2) |
| `compare__<model>.sql` (N files) | Full row+column classified diff via `compare_and_classify_query_results` | Step 5 (deep dive) |

> **Pattern**: `col_diff_a__` and `col_diff_b__` are `materialized='view'` models that apply the
> date filter. The `col_diff__` comparison view reads from these. Ephemeral models do **not** work
> as relations for `compare_all_columns` - the macro needs a real warehouse object to introspect
> the column list.
